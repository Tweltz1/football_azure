# ToteTrack iPhone app

Put a QR label on every storage tote, then scan it to see or change what's inside.
Built with Expo (React Native). GitHub builds it on a macOS machine
(`.github/workflows/totetrack-app.yml`), so no Mac is needed.

## What it does
- **Totes**: name, storage location, color, icon, photo and notes. Home screen searches every item
  in every tote ("where are the tent stakes?").
- **Items**: quick add ("3 beach towels" sets qty 3), +/− quantities, rename, move to another tote.
- **Scan**: in-app scanner, or the iPhone Camera app: each label is `totetrack://tote/<id>`, which opens
  the tote directly. Scanning a label that isn't linked yet goes straight to "set up this tote".
- **Print**: AirPrint or PDF. Big one-per-page tote sign (optionally with contents list), Avery 5163
  (2"×4"), Avery 22806 (2" square) and Avery 5160 (1"×2⅝") sheets, blank labels to pre-print, "skip used
  labels" for partly used sheets, and cut guides for plain paper.
- Data stays on the phone (no account, no server).

## Layout
- `src/app/` screens (Expo Router): `index` home, `scan`, `print`, `tote/[id]` detail, `tote/edit`.
- `src/lib/` store (AsyncStorage), QR matrix (`qr.ts`), printable label HTML (`labels.ts`), photos.
- `app.json` name, bundle ID `com.tweltz1.totetrack`, URL scheme, permission texts.
  `app.config.js` takes the build number from the workflow run number.
- `ios/` is generated by `expo prebuild` on the build machine and is not committed.

## Builds (TestFlight)
- Any push touching `totetrack-app/` builds for the simulator and pushes screenshots to the
  `totetrack-screenshots` branch.
- Put `[totetrack-upload]` in a commit message (or Actions > ToteTrack iPhone app > Run workflow >
  tick "Upload to TestFlight") to send a build to TestFlight. Uses the repo's existing
  `APPLE_TEAM_ID`, `APP_STORE_CONNECT_KEY_ID`, `APP_STORE_CONNECT_ISSUER_ID`, `APP_STORE_CONNECT_KEY`.

## Local dev (optional)
`npm install`, then `npx expo start`. The camera scanner and printing need a dev build on a phone.
